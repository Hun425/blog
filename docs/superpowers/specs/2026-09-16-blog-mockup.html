왜 지금 TDD인가

기능 추가마다 회귀가 터지던 시점이었다. 수동 QA에 하루가 통째로 들어가는 상황을 보면서, 테스트를 나중에 붙이는 방식으로는 이 부채를 갚을 수 없다고 판단했다.

테스트가 먼저 있어야 리팩토링이 가능하고, 리팩토링이 가능해야 설계가 나아진다.

첫 번째 시도와 저항

팀의 반응

"일정이 두 배로 늘어난다"는 우려가 가장 컸다. 실제로 첫 스프린트는 느렸다. 하지만 두 번째 스프린트부터 버그 티켓이 눈에 띄게 줄었다.

도구 선택

JUnit 5와 Kotest 사이에서 고민하다가 팀이 이미 익숙한 JUnit 5를 선택했다. 도구보다 습관이 먼저였다.

// 실패하는 테스트를 먼저 쓴다
@Test
fun `주문 금액이 0원이면 결제를 거부한다`() {
    val order = Order(amount = 0)
    assertThrows<InvalidOrderException> { paymentService.pay(order) }
}

두 달 뒤 지표

지표도입 전도입 후
스프린트당 회귀 버그7건2건
수동 QA 시간8시간2시간
라인 커버리지11%58%

숫자 자체보다 팀이 리팩토링을 두려워하지 않게 된 변화가 더 컸다. 다음 편에서는 레거시 코드에 테스트를 끼워 넣는 기법을 다룬다.
